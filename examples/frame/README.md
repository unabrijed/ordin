# Frame tester app

**Live app: https://frame-api-production-7da3.up.railway.app**

Frame demonstrates Ordin subscriptions with premium PNG generation and API access. Railway serves the UI, merchant API and recurring-payment worker together. Billing state and transaction recovery data live in SQLite on its persistent `/data` volume. No separate database service or scheduler is needed.

## Test a subscription

Connect your customer wallet on Whitechain Sepolia (1874), open **Subscription → Start with Ordin**, approve 3 test USDT, then sign the subscription terms. Frame charges 1 USDT per 120-second window, for at most three windows. The merchant sponsors registration, renewal and cancellation; the customer pays the initial token approval gas.

After a confirmed payment, premium access unlocks. Keep the subscription active to observe automatic renewal, then cancel future collections. Save explorer links from the UI as payment evidence.

## Files

- `index.html`, `style.css`, `app.js`: browser UI.
- `checkout.js`: reusable wallet/checkout adapter.
- `../../services/merchant`: API, billing worker, SQLite and transaction recovery.

For local hosting against Whitechain, configure the root `.env` and run `yarn frame` from the repository root. Use `yarn frame:local` only for the optional local EVM sandbox.

## Requirements

- Node.js **22.14 or newer**, and **Yarn Classic 1.22.22**. Install from the repository root using `yarn install --frozen-lockfile`.
- One always-running Railway instance with the root Dockerfile, port 8080, sleeping disabled, and a persistent volume mounted at `/data`. Both SQLite billing and queue files must persist across restarts.
- Root `.env` for local development; Railway service variables for hosting: `ORDIN_ADDRESS`, `WHITECHAIN_RPC_URL`, `MERCHANT_PRIVATE_KEY`, `MERCHANT_TREASURY`. The Railway public domain supplies the browser origin; set `FRAME_ORIGIN` only to override it deliberately.
- Merchant WBT for sponsored transactions. Customer WBT for approval and the exact official test USDT listed in the runbook.
- A modern browser with an injected EVM wallet for signing. Rendering and billing require a network connection; the app is not an offline PWA.
- Check `/api/ready` for HTTP 200 before a demo. No Postgres service, external cron, or new Ordin deployment is required.

## Page metadata and assets

`index.html` includes the page title, description, canonical URL, Open Graph and Twitter preview metadata. `favicon.svg` and `site.webmanifest` supply the app identity. `social-preview.png` is a public 1200 × 630 card generated by Frame's own renderer. The merchant server explicitly serves these files.

This is a testnet tester, so `robots.txt` and the robots meta tag request no search indexing. They are not access controls. No sitemap is published for this single-page test app. If the public hostname changes, update the canonical URL and all absolute social-image/page URLs in `index.html` together.
